本地运行的论文研究与写作工作台，计划在 GitHub 开源。需求依据见 outputs/ 目录下的《01-论文工作台-产品与技术方案.md》与《02-论文工作台-AI开发交接提示词.md》。

## 当前进度

### 已实现（阶段 1）

- 创建项目：学科多选 + 研究方法选择 + 已有材料入口（题目/文献/数据/初稿，可稍后补充）
- 13 个论文阶段导航；状态流转：未开始 / 进行中 / 待确认 / 已完成 / 已跳过（可恢复，记录原因）
- 三种研究方法模板（化学与材料实验 / AI 算法 / 问卷定量）：同一阶段按方法展示不同输入与记录结构；其余方法明确标注「模板待补充」
- 阶段工作区统一结构：目标 / 需要什么材料 / 你要做什么 / 会得到什么 / 检查清单 / 下一步 + 模板字段 + 自动保存
- 本地 SQLite 持久化（Electron 内置 node:sqlite，无原生模块），关闭重开内容恢复
- 带材料进入：自动建议起始阶段，中间阶段标记「已有材料」，项目首页展示材料缺口提示

### 已实现（阶段 2）

- 服务与模型设置：主流服务商预设 + 自定义 OpenAI 兼容中转 / Anthropic 风格
- API Key 经系统安全加密（safeStorage）存储，只存密文；界面与日志中不出现明文
- 网络方式：直连 / 跟随系统代理 / 自定义代理
- 三层连接测试：鉴权 → 模型可用 → 实际能力，支持取消
- 五个任务角色（检索辅助 / 研究设计 / 写作 / 分析解释 / 审阅）分别分配服务商与模型

### 已实现（阶段 3）

- 文献库：真实学术数据源适配器（Crossref 书目/DOI 核验、arXiv 预印本、PubMed 生物医学），检索式、来源与时间写入检索记录；无结果与失败明确返回
- 手动录入（默认「待核验」）、人工核验（含核验说明）、RIS/BibTeX 导入、按 DOI/标题去重、预印本与正式发表区分
- 证据卡片（观点 + 原文定位）、用户 PDF 关联（复制到本地附件目录，仅记录文件名，不声称解析全文）
- 国内平台（知网/万方/维普）官方入口 + 可复制检索式 + 人工核验记录，不虚构 API

### 已实现（写作管线 · 全流程论文 RAG）

- 写作阶段「AI 写作」：检索文献库（题录/摘要/证据卡片）→ 拼【材料清单】→ 调「写作」角色模型（可配 deepseek-v4-pro）→ 输出正文草稿 / 论断清单 / 缺口清单 / 下一步
- 引用 [@ref_N] 只对应真实来源且可点击核对；正文出现清单外编号会明确告警；无「待核验」占位，缺料进缺口清单
- 原版设计稿见 docs/rag-pipeline-reference/（提示词中正文/引用/gap 约束与原版一致）

### 已实现（阶段 4）

- 选题工作台：AI 生成候选方向（研究问题 / 来源依据 / 数据路径 / 可行性 / 限制）；依据只能引用本项目文献库，编造引用自动标「来源待核验」
- 研究设计 AI 起草：按方法模板字段生成草稿；问卷方法生成结构化假设卡片（H 编号 / 陈述 / 自变量 / 因变量 / 依据），不强制中介调节变量
- 开题报告框架生成（章节标题 + 内容，可编辑）
- 版本管理：研究设计与开题报告可保存版本快照、恢复旧版本；恢复时提示下游内容需人工复核，不覆盖旧版本
- 带题目进入流程与从零选题流程均已覆盖

## 运行与验证

```bash
npm install          # 网络受限时可先设置 ELECTRON_MIRROR=https://npmmirror.com/mirrors/electron/
npm run dev          # 开发模式（vite + electron）
npm test             # 单元测试（29 个用例）
npm run test:electron # 桌面端到端测试（5 个用例：主流程 + 三类模板 + 模型配置 + 文献链路 + 阶段 4；使用独立临时 userData，不读写日常数据）
npm run desktop:pack # 打包为解包目录（release/win-unpacked）
```

验证证据：单元测试 29/29；electron 端到端 5/5（阶段 4 用本地模拟模型与 Crossref 服务覆盖选题/起草/假设/开题/版本/重启恢复）；真实调用已验证：DeepSeek 三层连接测试、真实候选方向生成（5 条，文献列表外依据一律标「来源待核验」，无编造）、开题框架生成（5 个章节）、Crossref DOI 核验与书目检索（用户真实邮箱）、arXiv/PubMed 各 10 条真实结果。
